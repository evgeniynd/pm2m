Веб-панель на Node.js для управления локальным PM2 и несколькими Linux-серверами по SSH.

Возможности: переключение серверов, CPU/RAM процессов, поиск и фильтр статуса, запуск приложения, start/stop/restart/reload/delete, просмотр stdout/stderr с обновлением, сохранение списка PM2. Настройки серверов добавляются и редактируются через интерфейс.

## Запуск на Linux

Требуется Node.js 22+ и npm. Установите зависимости в папке проекта:

```bash
npm ci
cp .env.example .env
```

В `.env` задайте собственный непустой `ADMIN_PASSWORD`. Минимальная длина не ограничена. Затем:

```bash
npm start
```

Панель: http://127.0.0.1:3100. Для доступа с другой машины можно использовать SSH-туннель:

```bash
ssh -L 3100:127.0.0.1:3100 deploy@panel-server
```

Для доступа через домен направьте HTTPS reverse proxy на `127.0.0.1:3100`, задайте `COOKIE_SECURE=true`. `HOST=0.0.0.0` разрешает слушать внешние интерфейсы; передавать пароль панели следует через HTTPS. Панель рассчитана на одного доверенного администратора: управление PM2 позволяет запускать код с правами пользователя PM2.

## Настройки серверов

Откройте «Настройки серверов» → «Добавить сервер».

**Локальный PM2:** выберите локальное подключение. Используется PM2 текущего пользователя и `PM2_HOME` из окружения панели. Запускайте панель от того же пользователя, что и приложения. Без действующего PM2 подключение может создать локальный daemon. Для локального подключения все профили используют один и тот же daemon.

**SSH:** задайте название, адрес, порт, пользователя и способ входа:

- Пароль SSH.
- Путь к приватному SSH-ключу на машине, где работает панель; для зашифрованного ключа задайте пароль ключа.

Нажмите «Получить отпечаток». Эта операция получает публичный ключ без передачи пароля. Сверьте SHA256-отпечаток с ключом сервера через доверенный канал. На сервере его можно посмотреть, например:

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

Сохранённый отпечаток закрепляется за подключением. При изменении ключа доступ блокируется; проверенный новый отпечаток можно сохранить в настройках. Ключ, выбранный SSH при согласовании, может иметь другой алгоритм — в таком случае сравните соответствующий публичный host key.

В дополнительных настройках доступны абсолютный путь к PM2 и `PM2_HOME`. PM2 должен быть установлен на удалённой машине. Команды выполняются через `bash -lc` от выбранного SSH-пользователя, без `sudo`. Если команда `pm2` не видна, панель автоматически загружает nvm из `$NVM_DIR/nvm.sh` или `~/.nvm/nvm.sh`. Для явно заданного пути к PM2 его папка добавляется в PATH, чтобы находился установленный рядом Node.js. При нестандартной установке можно указать wrapper, который выставляет окружение и запускает PM2. Путь к PM2 — это один исполняемый файл, а не произвольная shell-команда.

Кнопка «Проверить» подключается к PM2 и запрашивает процессы. SSH-подключение создаётся для каждого запроса; требуется разрешённое выполнение команд. Метрики отображают CPU/RAM процессов, не суммарную нагрузку удалённого Linux. Логи ограничены последними 200 строками / 128 КБ на поток и обновляются раз в 5 секунд.

## Где хранятся данные

Внутри проекта автоматически создаётся папка `data/`:

```text
data/
  settings.json   # профили серверов; SSH-секреты зашифрованы AES-256-GCM
  secret.key      # ключ шифрования
```

Сохраняйте оба файла при переносе и резервном копировании. На Linux папка создаётся с правами `0700`, файлы — `0600`. Доступ к обоим файлам позволяет расшифровать пароли. Папка исключена из Git. Ключи SSH остаются по указанным путям и не копируются в проект. При редактировании пустой пароль сохраняет предыдущий секрет; смена типа авторизации сбрасывает прежний секрет. Сессии входа сохраняются в `data/sessions.json` (для деморежима — `data/demo/sessions.json`) и переживают перезапуск панели. Браузер хранит случайный токен в HttpOnly-cookie; пароль в cookie не записывается. Срок cookie — 400 дней с продлением при использовании панели. Выход из аккаунта отзывает сессию, смена ADMIN_PASSWORD отзывает все сессии при перезапуске. После обновления со старой версии понадобится один повторный вход.

## Работа с процессами

«Новое приложение» принимает имя, абсолютный путь к скрипту и рабочую папку **на выбранном сервере**. Приложение запускается в fork mode. `Reload` обеспечивает плавную перезагрузку для приложений в cluster mode; в fork mode возможен обычный restart. Удаление процесса удаляет его из PM2, но не удаляет файлы приложения.

При открытии формы панель проверяет установленные версии Node.js на выбранном сервере. Выберите версию в поле «Версия Node.js»; рядом указан точный путь. PM2 получает этот путь как `interpreter` (по SSH — `--interpreter`). Перед запуском доступность выбранной версии проверяется повторно. Кнопка «Проверить версии ещё раз» обновляет список; при ошибке поиска или пустом списке запуск заблокирован.

На Linux поиск охватывает PATH, стандартные системные пути, nvm, n, fnm, asdf, nodenv и Volta текущего пользователя. Панель проверяет исполняемые файлы через `node --version` и убирает дубликаты символьных ссылок. Произвольные папки и установки других пользователей не сканируются. Для локальной панели на Windows проверяются текущий Node.js, PATH, nvm-windows и Volta. В локальном деморежиме список версий демонстрационный; для SSH всегда используются реальные данные сервера.

«Сохранить список PM2» соответствует `pm2 save`. Для автозапуска после перезагрузки самого Linux отдельно настройте `pm2 startup` на каждом сервере. Локальная панель защищена от остановки собственного процесса через интерфейс. Если подключаться к её хосту по SSH, не останавливайте панель через этот профиль.

## Запуск панели как службы

Пример unit-файла находится в `deploy/pm2m.service.example`. Измените пользователя и абсолютные пути, затем установите unit в `/etc/systemd/system/pm2m.service`:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now pm2m
```

Пользователь службы должен иметь доступ к папке проекта, файлам SSH-ключей и локальному PM2, если он используется.

При запуске самой панели через PM2 укажите файл `server.js`, рабочую папку проекта и Node.js 22+. Панель автоматически читает `.env` из своей папки, включая запуск через контейнер PM2. Путь к папке проекта нельзя использовать вместо пути к скрипту.

## Деморежим и проверки

```bash
npm run demo
# Пароль demo, если ADMIN_PASSWORD не задан в .env
npm test
```

В деморежиме локальные процессы демонстрационные, изменения живут в памяти. Настройки сохраняются отдельно в `data/demo/`. SSH-профили подключаются к настоящим серверам и выполняют реальные действия. На Windows можно использовать панель для управления Linux по SSH.

Интеграция основана на [PM2 API](https://pm2.keymetrics.io/docs/usage/pm2-api/) и [SSH2](https://github.com/mscdex/ssh2).

## Telegram

В настройках панели добавьте токен отдельного бота от @BotFather, включите бота и сохраните. Отправьте ему `/id` в личном чате и добавьте полученный числовой ID в разрешённый список в панели. Пока список пуст, бот только показывает ID, управление недоступно. Несколько ID указываются через запятую. Каждый разрешённый пользователь открывает меню командой `/start`. Управление в группах отключено. Все разрешённые пользователи имеют доступ ко всем настроенным серверам, управлению процессами и логам.

Меню: сервер → приложение → старт, стоп, рестарт, reload, удаление из PM2 или последние 30 строк stdout/stderr. Изменения требуют подтверждения; подтверждения одноразовые, меню действует 15 минут. Есть сохранение списка PM2 на сервере. После перезапуска панели откройте новое меню командой `/start`.

Кнопка «Загрузить приложения серверов» позволяет выбрать приложения для уведомлений. Отслеживаются новые записи stderr (даже если процесс online), изменения статуса, счётчика рестартов, удаление приложения, потеря и восстановление подключения. Опрос каждые 30 секунд: краткие переходы статусов между опросами могут быть пропущены. Выбор привязан к серверу, имени и пути скрипта; экземпляры cluster отслеживаются вместе. При запуске панели фиксируется исходное состояние без рассылки старых событий и логов. Курсор stderr учитывает дописывание одинаковых ошибок, ротацию и очистку файла. За одну проверку читается до 64 КиБ новых данных; уведомление содержит до 30 последних строк, длинный текст сокращается. Stdout не читается для уведомлений, даже если содержит ERROR или Exception. Его можно посмотреть по кнопке логов в боте. При сбое отправки курсор сохраняет прежнюю позицию для повтора; после перезапуска панели или сохранения Telegram-настроек начинается новое наблюдение.

Токен шифруется вместе с настройками проекта и не возвращается в браузер. Используется исходящий long polling [Telegram Bot API](https://core.telegram.org/bots/api#getupdates); отдельный входящий порт не нужен. Запускайте только один экземпляр панели с этим токеном. Бот с настроенным webhook не запускается, чтобы не нарушить работу другой интеграции. Отметка обработанного обновления сохраняется перед исполнением: при аварии команда может потеряться, но не будет автоматически повторена.

## Анализ ошибок через Groq

В настройках веб-панели откройте «ИИ · Groq», вставьте ключ из https://console.groq.com/keys и включите анализ. По умолчанию используется `openai/gpt-oss-20b` через Groq API, модель можно изменить. Бесплатная квота зависит от аккаунта и модели; панель не включает оплату и не переключает тариф. Ключ зашифрован в settings.json, в API браузеру возвращается только признак наличия.

Под новыми уведомлениями stderr появится «ПРОАНАЛИЗИРОВАТЬ». По нажатию разрешённого пользователя бот отправляет в Groq снимок новых записей stderr на момент уведомления (до 100 строк, весь контекст до 12 000 символов), имя сервера, имена/ID процессов, статус и число рестартов. stdout, SSH-реквизиты и переменные окружения в контекст не включаются. Известные ключи и распознаваемые секреты маскируются; фильтр не гарантирует удаления всех конфиденциальных данных произвольного формата.

Ответ возвращается обычным текстом в тот же личный чат, длинные ответы делятся на сообщения. Команды ИИ не исполняются. Одновременно выполняется один анализ, не более одного нового анализа в минуту на Telegram-пользователя. Успешный результат повторно выдаётся из памяти без запроса в Groq. Кнопки действуют до 24 часов, пока не перезапущена панель или бот; при переполнении памяти меню старые кнопки вытесняются. Сохранение Groq перезапускает бота и сбрасывает меню/курсоры наблюдения. Ошибки API показываются без ключей и тела ответа поставщика; автоматических повторов платных/лимитируемых запросов нет.

Без ключа интеграция выключена. Тесты используют подставной Groq API: реальные логи внешнему сервису при тестировании не отправляются.
